# M3-C7: Google Routing & Distance

## API Selection
We will use the modern **Routes API** (`computeRouteMatrix` and `computeRoutes`) rather than the legacy Distance Matrix / Directions APIs. It offers better performance, field-masking to reduce payload sizes, and consolidated billing. For geocoding, we use the standard Geocoding API.

## Payload & Shapes
- `route_matrix`: Returns `distanceMeters` and `duration` for multiple destinations. Converted to km and minutes.
- `route`: Returns the same plus an `encodedPolyline` for drawing the route on the map.
- `geocode`: Translates text to `lat/lng`.

## Caching Strategy
A short-TTL LRU cache is maintained in memory.
- Key: origin/destination coordinates rounded to 4 decimal places (approx. 11m precision).
- This ensures users repeatedly querying the same origin to the same stations in a single session hit the cache instead of racking up Google billing.

## Cost Control (Nearest-K)
Google Routes API charges per element (origin × destination). To keep quotas low, the upstream Node service (M2) pre-filters stations using a simple, free **haversine** distance calculation, passing only the nearest `K` (e.g. 5-10) candidate stations to the ML service's `/route/matrix` endpoint.

## Graceful Fallback
If the `GOOGLE_SERVER_KEY` is missing, quota is exhausted, or the API times out:
- We automatically fallback to the local `haversine_km` function.
- Travel time is estimated assuming a flat `30 km/h` urban speed.
- All returned results set `isEstimated = true`. The UI will display "estimated" labels for these metrics.
