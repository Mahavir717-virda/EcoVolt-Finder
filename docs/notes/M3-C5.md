# M3-C5: Forecasting Model

## The Baseline First Approach
We prioritize a strong baseline before jumping into complex models (Prophet/XGBoost).
The chosen baseline predicts the **average renewable% by `hour-of-day` × `month` (season)**.
This is legitimate because grid generation (especially solar) is highly cyclical and seasonal. For example, 1 PM in July will look vastly different from 1 AM in January. By grouping historical data into these buckets, we capture the strongest signals (sunlight, peak demand times) without the overhead of a complex timeseries model.

## Optional Upgrades
Once the baseline is established, an XGBoost model could be added behind the same `Forecaster` interface using lag features and weather data. However, the baseline already sets a very high bar for accuracy on seasonal grid metrics.

## Confidence Derivation
Every predicted point includes a `confidence` metric [0, 1].
In our baseline, confidence is inversely proportional to the historical **standard deviation** within that specific hour/season bucket. 
- If 1 PM in July is always sunny with 80% renewables (low variance), confidence is ~0.9.
- If 6 PM in April is volatile due to shifting wind patterns (high variance), confidence drops.
Low-confidence points are explicitly flagged in the UI (e.g., greyed out) so the user never interprets a noisy guess as certainty.

## Backtest Validation
To ensure we don't overfit, we split the data chronologically (`train_test_split_temporal`). We calculate the **Mean Absolute Error (MAE)** of our bucketed baseline against the actual held-out test data, and compare it to a naive baseline (predicting the overall global mean). We write these metrics to `docs/notes/M3-C5-metrics.md`.
