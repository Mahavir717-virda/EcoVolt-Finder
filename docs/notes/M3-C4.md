# M3-C4: Historical Store & Feature Engineering

## Historical Schema
Data will be stored per zone as a CSV (for the demo) containing at least:
- `timestamp_utc`: ISO-8601 UTC timestamp
- `renewable_pct`: The renewable percentage (0-100)
- `carbon_intensity`: Carbon intensity (gCO2eq/kWh)

## Resampling
Raw data from APIs (like ElectricityMaps) may arrive irregularly. We will resample this to a fixed hourly frequency to ensure consistent lag features and model inputs. Missing values will be linearly interpolated up to a short gap limit.

## Feature Set
The feature builder will construct:
- **Time-based features**: `hour_of_day`, `day_of_week`, `month`
- **Lag features**: t-1, t-2, t-24 (previous day)
- **Rolling means**: 3-hour, 6-hour, 24-hour averages

## IST Handling
- All internal storage is strictly UTC.
- When generating time-based features (hour of day, day of week), the UTC timestamp MUST be converted to IST (UTC+05:30) first so that the features align with local human behavior (e.g., solar peaks during local noon).
- The conversion logic will be centralized to prevent bugs.

## Train/Test Split
For backtesting and avoiding data leakage:
- Features must be strictly generated using past data (no rolling windows centered or shifted into the future).
- Time-based splits will be used (e.g., earlier data for training, the latest available days for testing).
