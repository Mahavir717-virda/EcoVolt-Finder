## 1. Objectives & Scope

Implement station and operator endpoints with spatial search for **ecoVolt-finder**:
1. `GET /stations?lat&lng&radiusKm&connector&class&sort` — Returns `StationSummary[]`, pre-filtered and sorted by distance or greenness.
2. `GET /stations/:id` — Returns full station details (operator, zone, all connectors, tariffs, pricing rules).
3. `POST /stations` — Create a new charging station (Manager only).
4. `PATCH /stations/:id` — Update station details (Manager, ownership guarded via `requireStationOwnership`).
5. `GET /operators` — Read operator registry for manager profile and public listings.
6. `POST/PATCH/DELETE /stations/:id/connectors` — Connector management for operators.

---

## 2. Geo-Query Strategy: Haversine SQL Formula (Edge Case #26)

To avoid requiring PostGIS extensions while maintaining sub-millisecond query execution, we utilize the spherical **Haversine Distance Formula**:

$$d = 2 R \cdot \arcsin\left(\sqrt{\sin^2\left(\frac{\Delta \text{lat}}{2}\right) + \cos(\text{lat}_1) \cdot \cos(\text{lat}_2) \cdot \sin^2\left(\frac{\Delta \text{lng}}{2}\right)}\right)$$
where $R = 6371.0\text{ km}$.

- **Candidate Set Capping (Edge Case #26):** Geo search limits the result set to the nearest $K = 25$ candidate stations within `radiusKm` (default: 10 km, max: 100 km) to prevent downstream Google routing quota blowup.

## 3. StationSummary Assembly & Data Enrichment

Each returned station card matches `/contracts/types.ts:StationSummary`:
1. **Location:** `{ lat, lng }`
2. **Provider:** Power provider enum (`torrent_power`, `guvnl_gb`, `adani_energy`, `tata_power`, etc.) — **Edge Case #2**.
3. **Zone Mapping & Greenness:** Station foreign key `zoneId` maps to regional grid data. While ML service is starting, integration helper provides real-time/cached/mock snapshot with `DataQuality` tag (**Edge Case #3**).
4. **Connectors:** Maps connector list with `available` and `total` count.
5. **Cheapest Price (`priceFrom`):** Computed by finding minimum base tariff + provider markup across available connectors.

---

## 4. Key Edge Cases Addressed

- **Edge Case #3 (Greenness per Grid Zone):** Each station carries a first-class `zoneId` (e.g. `IN-WE`) enabling accurate regional greenness attribution.
- **Edge Case #10 (Connector & Vehicle Class Filtering):** Query parameters `connector` and `class` filter out incompatible stations or mark compatibility status.
- **Edge Case #22 (Manager Scoping & RBAC):** `POST /stations` requires `Role.manager`. `PATCH /stations/:id` verifies the station belongs to `req.user.sub`'s operator profile via `requireStationOwnership`.
- **Edge Case #26 (Candidate Cap for Routing):** Caps query returns to nearest $K$ stations to keep downstream route computation performant.
