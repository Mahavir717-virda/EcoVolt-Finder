## 1. Objectives & Scope

Build the integration layer in `/server/src/integrations` that:
1. **Fronts Member 3's ML Service (`openapi.ml.yaml`):**
   - Calls FastAPI endpoints: `/grid/live`, `/grid/forecast`, `/recommend`, `/estimate/windows`, `/smartcharge/plan`.
   - **Timeout & Resilience:** 2-second timeout per HTTP request.
   - **Hybrid Fallback (Edge Case #12):** When ML service is down or times out, seamlessly falls back to cached responses or canned JSON files in `/contracts/examples/` and sets `quality: DataQuality.MOCK` or `isEstimated: true`.
   - **In-Memory Short-TTL Cache:** 60-second cache for live grid snapshots and forecasts to reduce microservice traffic.
2. **Proxies Google Server-Side APIs (`googleProxy.ts`) (Edge Case #25):**
   - Handles server-side Geocoding, Directions, and Distance Matrix.
   - **Key Protection:** `GOOGLE_SERVER_KEY` is loaded from server `.env` and **never exposed to client responses**.
   - If Google key is absent or fails, falls back to deterministic local Haversine coordinates calculation.
3. **Exposes Node Backend Endpoints:**
   - `GET /recommendations?originLat&originLng&vehicleId&kwh`
   - `GET /forecast?zoneId&stationId`
   - `GET /grid/live?zoneId`

## 2. ML Client Interface & Fallback Hierarchy

```
App / Client Request
        │
        ▼
   [ Node API ] ──(Check 60s Cache)──▶ Hit? Return Cached (DataQuality.CACHED)
        │
        ├──(Try HTTP to ML Service: http://localhost:8000, 2s Timeout)
        │       ├── Success? ──▶ Return Live (DataQuality.LIVE) & Cache
        │       └── Failed / Timeout?
        │               │
        │               ▼
        └───────▶ [ Load /contracts/examples/*.json ] ──▶ Return Mock (DataQuality.MOCK)
```

## 4. Key Edge Cases Addressed

- **Edge Case #12 (Grid API down / no wifi):** Hybrid data layer: Try live microservice $\rightarrow$ short TTL cache $\rightarrow$ `/contracts/examples/` mock; always tags `DataQuality` honestly (`live`, `cached`, `mock`).
- **Edge Case #25 (Google key leakage):** Client app never holds the Google server key; routing and geocoding are proxied server-side.
- **Edge Case #26 (Google quota protection):** In-memory cache + nearest $K=25$ candidate filter prevents quota explosion.

---

## 5. Acceptance Criteria & Test Plan

1. When ML service is down or unreachable, `GET /recommendations` returns valid mock-tagged `StationRecommendation[]` without crashing.
2. `GET /forecast?zoneId=IN-WE` returns 24-hour forecast points.
3. Google server key is never exposed in any JSON response.
4. Full test suite passes and `tsc` builds cleanly with 0 errors.
