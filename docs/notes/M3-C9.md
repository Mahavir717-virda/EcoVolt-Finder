# M3-C9: Recommendation & Ranking Engine

## The Scoring Logic
The engine's goal is to protect users from the "sticker trap"—where a station advertises a very cheap ₹/kWh rate, but is so far away that the vehicle consumes more energy (and money) driving there than is saved on the charge.

For each candidate station, we calculate:
1. `chargingCost = finalPricePerKwh × energyNeededKwh`
2. `travelCost` = (calculated via the M3-C8 module)
3. `trueTotalCost = chargingCost + travelCost`

### The Time Penalty
To avoid recommending a station that is only ₹1 cheaper but takes 30 minutes longer to reach, we blend a small time penalty into a final `sortScore`.
`sortScore = trueTotalCost + (travelMinutes × timePenaltyRate)`

### The Sticker Trap Delta
To explicitly educate the user, we calculate `vsCheapestSticker`:
1. Find the station(s) with the absolute lowest `finalPricePerKwh` (the naive pick).
2. Note the `trueTotalCost` of this naive pick.
3. For every station: `vsCheapestSticker = naivePickTrueTotalCost - thisStationTrueTotalCost`.
If positive, this station actually saves the user money overall despite having a higher sticker price. 

## Filters & Edge Cases
- `connectorCompatible`: True if there is an intersection between the vehicle's connectors and the station's connectors. Incompatible stations are always pushed to the bottom of the list.
- `reachable`: Evaluated via M3-C8. Unreachable stations are also pushed to the bottom.
- Only the top K stations (pre-filtered by the Node service) are processed here to limit Google Routes API calls.

## Greenness Tie-Breaks
If two stations have near-identical `trueTotalCost`, we could integrate the `expectedRenewablePct` as a tie-breaker. This allows users to subtly charge greener without feeling an economic penalty.
