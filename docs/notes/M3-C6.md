# M3-C6: Cost/greenness time-slot estimator

## 1. Combining Forecast Renewable% with Tariff

The goal is to generate per-hour window estimates containing `{price, renewablePct, confidence}` for a given `zoneId`.
- **renewablePct** and **confidence** come from the forecasting module (`ml.app.forecast`).
- **price** is computed using the base `tariff` and a Time-of-Use (ToU) adjustment.

## 2. ToU Tariff vs Transparent Modeled Proxy

We need to flag when the price uses a **published ToU tariff** vs a **transparent modeled proxy**. 
- **Published ToU Tariff**: Some zones might have a strict, published ToU schedule (e.g. fixed ₹/kWh discount during specific daytime hours). When we apply this published schedule, `isEstimate` is `False`.
- **Modeled Proxy**: When a published ToU schedule is absent, we use a proxy formula based on the renewable percentage. In this case, `isEstimate` is `True`.

### Proxy Formula
The proxy formula should be simple and identical in spirit to Member 2's pricing engine.
A straightforward approach:
- Baseline renewable% = 50%
- Adjustment factor = 0.05 ₹/kWh per 1% deviation from baseline.
- `touAdjustment = (50 - renewablePct) * 0.05`
  - If `renewablePct` = 80%, `touAdjustment` = -1.5 ₹/kWh (Discount)
  - If `renewablePct` = 20%, `touAdjustment` = +1.5 ₹/kWh (Premium)
- **Floor**: We clamp the final price to a floor to ensure the price doesn't go below a certain minimum (e.g. 50% of the base tariff or a hard minimum of 2 ₹/kWh).
  - `estimatedPricePerKwh = max(tariff * 0.5, tariff + touAdjustment)`

## 3. "Best Window" Selection

Given a `durationH` (e.g., 2.5 hours), the `best_window` should be selected as the "greenest affordable window".
- We calculate the rolling average of `renewablePct` and rolling average of `estimatedPricePerKwh` over a contiguous block of `durationH` hours.
- **Selection criteria**: We want to maximize renewable% while keeping the cost low. 
- A simple scoring function for a window block: 
  - Normalize cost (lower is better) and greenness (higher is better).
  - Or simply: pick the block that minimizes `estimatedPricePerKwh` first, and if tied (or within a small threshold), maximizes `renewablePct`.
  - Alternatively: since lower price correlates with higher renewable% in the proxy, picking the highest average `renewablePct` naturally minimizes the proxy price. However, if a published ToU tariff applies, they might diverge slightly. So we select the block that minimizes `estimatedPricePerKwh`, using `renewablePct` as a tie-breaker.

## 4. Edge Cases (#14)
- **Estimate vs Published**: Clearly flagged via `isEstimate`.
- **Consistent Pricing**: The logic for proxy calculation will be shared conceptually with the backend (M2).
- **Duration**: Rolling window calculations must handle fractional hours correctly (or round up to integer blocks for simplicity, but the instruction says `durationH` which might be float).
