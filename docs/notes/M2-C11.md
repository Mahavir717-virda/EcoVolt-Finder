## 1. Objectives & Scope

Implement a structured, extensible notification and incentive nudging system for **ecoVolt-finder**:
1. **Notification Provider Abstraction (`NotificationProvider`):**
   - Clean interface allowing seamless switching between `MockNotificationProvider` (for test/offline demo without external dependencies) and `ExpoPushNotificationProvider` (delivering push messages via Expo Push API to React Native mobile clients).
2. **Key Event Triggers & Nudges:**
   - **Green Window Nudge (Edge Case #7):** "Your optimal solar charging window is starting now — save ₹X with peak renewable electricity!"
   - **Booking Reminder:** Reminder sent 15 minutes before the reserved charging window.
   - **Connector Offline Alert (Edge Case #18):** When a connector goes offline/enters maintenance, immediately notify all drivers with pending bookings for that connector so they can reroute.
   - **Session Completed Summary:** Notifies driver upon session completion with total energy delivered, cost at locked price, and $CO_2$ avoided.
3. **API Endpoints:**
   - `POST /notifications/token`: Register Expo Push token for current user profile.
   - `GET /notifications`: Retrieve notification history for the authenticated user.
   - `PATCH /notifications/:id/read`: Mark notification as read.

---

## 3. Key Edge Cases Addressed

- **Edge Case #7 (Driver Habituation & Incentive Nudges):** Real-time green window alert nudges drivers to shift charging into high-renewable hours.
- **Edge Case #18 (Connector Outage Mid-Schedule):** Alerts affected drivers if a booked connector is marked maintenance/offline.
- **Offline / Test Resiliency:** Default to mock provider so tests and demos run without external Expo network calls.

## 4. Acceptance Criteria & Test Plan

1. Notification events (`sendNotification`, `notifyGreenWindow`, `notifyConnectorOffline`, `notifySessionComplete`) enqueue notifications properly.
2. `POST /notifications/token` registers user push token.
3. `GET /notifications` returns notification history list for user.
4. `PATCH /notifications/:id/read` marks a notification as read.
5. All tests pass with Supertest and `tsc` builds cleanly with 0 errors.
