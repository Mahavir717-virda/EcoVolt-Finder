## 1. Objectives & Scope

Set up the core backend foundation in `/server`:
- Express application with TypeScript.
- Environment configuration with validation (`dotenv` + `zod` / structured config loader).
- PostgreSQL database integration using Prisma ORM.
- Docker Compose setup (`docker-compose.yml`) for running local PostgreSQL.
- Structured response and error envelope (`{ error: { code, message, details? } }`).
- Structured request logging (HTTP middleware with `morgan` / `pino` or structured console).
- Security middleware: `helmet`, `cors`, and `express-rate-limit`.
- Health check route: `GET /health` verifying database connectivity and basic service status.
- Interactive OpenAPI documentation served at `/docs` (using `swagger-ui-express` loaded from `/contracts/openapi.node.yaml`).
- Standard `.env.example` and `.gitignore`.

## 3. Configuration & Environment Strategy

We use `zod` and `dotenv` to parse and strictly validate environment variables on boot:
- `PORT`: Server port (default: `4000`)
- `NODE_ENV`: `'development' | 'production' | 'test'` (default: `'development'`)
- `DATABASE_URL`: PostgreSQL connection string (e.g., `postgresql://postgres:postgres@localhost:5432/ecovolt?schema=public`)
- `JWT_SECRET`: Secret key for signing access tokens
- `JWT_REFRESH_SECRET`: Secret key for signing refresh tokens
- `ML_SERVICE_URL`: Base URL for Member 3's FastAPI microservice (default: `http://localhost:8000`)
- `GOOGLE_SERVER_KEY`: Server-side Google Maps key (optional during initial bootstrap, required for M2-C9)
- `CORS_ORIGINS`: Comma-separated list of allowed origins (e.g., `http://localhost:19006,http://localhost:3000`)

If any required variable is missing or malformed, the process exits immediately with a descriptive startup error.

## 4. Error & Response Envelope Shape

All error responses strictly follow the contract schema defined in `/contracts/openapi.node.yaml`:
```json
{
  "error": {
    "code": "BAD_REQUEST",
    "message": "Invalid query parameters provided",
    "details": {
      "field": "lat",
      "reason": "Must be a valid number"
    }
  }
}
```

Standard error classes (`AppError`, `NotFoundError`, `UnauthorizedError`, `ForbiddenError`, `ConflictError`, `ValidationError`) will inherit from `Error` and contain HTTP status codes and machine-readable error codes.

---

## 5. Logging Approach

- Production-grade HTTP request logging.
- Captures HTTP method, status code, URL, duration (ms), IP address, and request ID.
- Suppresses noisy `/health` logs in production or development to keep logs clean.

---

## 6. OpenAPI Synchronization Strategy

- `/contracts/openapi.node.yaml` is the single source of truth across all three members.
- `server` mounts Swagger UI at `GET /docs`, serving directly from the file in `../contracts/openapi.node.yaml` (using `yamljs` or `fs.readFileSync`).
- Any updates to the API endpoints will directly read this spec, ensuring no schema drift between frontend and backend documentation.

---

## 7. Database & ORM Strategy

- **Prisma ORM** will manage the connection pool to PostgreSQL.
- Initial schema in `prisma/schema.prisma` will define a minimal database setup.
- Health check runs a lightweight ping (`SELECT 1` via `prisma.$queryRaw`) to verify connectivity.
- Local PostgreSQL provided via `docker-compose.yml` mapped to port `5432`.

---

## 8. Health Check Contract (`GET /health`)

Returns HTTP 200 when database and server are healthy:
```json
{
  "status": "ok",
  "service": "ecovolt-server",
  "version": "1.0.0",
  "timestamp": "2026-09-12T00:30:00.000Z",
  "database": {
    "status": "connected",
    "latencyMs": 4
  }
}
```
If the database connection fails, it returns HTTP 503 Service Unavailable with `database.status: "disconnected"` and the standard error envelope.

---

## 9. Verification & Acceptance Criteria

1. `docker-compose up -d` boots PostgreSQL.
2. `npm run dev` starts Express server on port 4000.
3. `curl http://localhost:4000/health` returns `200 OK` with `status: "ok"` and `database: { status: "connected" }`.
4. `curl http://localhost:4000/docs/` serves interactive Swagger UI documentation.
5. Triggering a 404 returns `{ error: { code: "NOT_FOUND", message: "..." } }`.
6. `npm run build` runs `tsc` with zero type errors.
