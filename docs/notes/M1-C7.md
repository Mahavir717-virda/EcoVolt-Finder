## 1. Overview & Vehicle Context Architecture

The active vehicle profile provides the vital telemetry parameters required across the entire app:
1. **Range Calculation**: $\text{Remaining Range (km)} = \frac{\text{Battery Capacity (kWh)} \times (\text{Charge } \% / 100) \times 1000}{\text{Efficiency (Wh/km)}}$.
2. **Travel Cost Estimation**: $\text{Travel Cost (₹)} = \frac{\text{Distance (km)} \times \text{Efficiency (Wh/km)}}{1000} \times \text{Tariff Rate (₹/kWh)}$.
3. **Connector Filtering**: Matches station plugs against the vehicle's supported connector set (`connectors[]`).

```
┌────────────────────────────────────────────────────────┐
│                   Active Vehicle Store                 │
│   (persisted via expo-secure-store & zustand)          │
└───────────────────────────┬────────────────────────────┘

         ┌──────────────────┼──────────────────┐
         ▼                  ▼                  ▼
   [ Driver Map ]    [ Station Detail ]  [ Route Compare ]
   Range reach check   Connector matching  Travel cost ₹/km
```

## 2. Sensible Per-Class Defaults

When the driver selects a vehicle class via `SegmentedControl`, defaults are automatically populated:

| Parameter | 🚗 4-Wheeler (Car) Default | 🛵 2-Wheeler (Bike) Default |
|---|---|---|
| **Typical Battery** | $40.5\text{ kWh}$ (e.g. Tata Nexon EV Max) | $3.7\text{ kWh}$ (e.g. Ather 450X / Ola S1) |
| **Default Efficiency** | $140\text{ Wh/km}$ | $40\text{ Wh/km}$ |
| **Default Connectors** | `[CCS2, TYPE2_AC]` | `[THREE_PIN, BHARAT_AC_001, TYPE2_AC]` |
| **Default Charge %** | $42\%$ | $50\%$ |
| **Model Presets** | Tata Nexon EV, MG ZS EV, Mahindra XUV400 | Ather 450X, Ola S1 Pro, TVS iQube |

## 3. Form Validation with Zod (`features/vehicles/validation.ts`)

```ts
export const vehicleSchema = z.object({
  vehicleClass: z.enum(['car', 'bike']),
  model: z.string().min(2, 'Please enter a vehicle model name').max(50),
  batteryKwh: z.coerce
    .number()
    .positive('Battery capacity must be greater than 0 kWh')
    .max(250, 'Battery capacity cannot exceed 250 kWh'),
  efficiencyWhKm: z.coerce
    .number()
    .positive('Efficiency must be greater than 0 Wh/km')
    .max(500, 'Efficiency cannot exceed 500 Wh/km'),
  connectors: z
    .array(z.nativeEnum(ConnectorType))
    .min(1, 'Please select at least one compatible connector'),
  currentChargePct: z.coerce
    .number()
    .min(0, 'Charge percentage cannot be negative')
    .max(100, 'Charge percentage cannot exceed 100%'),
});
```

## 4. Edge Cases Handled

| Edge Case | Solution & UX Behavior |
|---|---|
| **#11 Class defaults differ** | Switching `SegmentedControl` between Car and Bike automatically sets class-appropriate battery ($40.5\text{ kWh}$ vs $3.7\text{ kWh}$), efficiency ($140$ vs $40\text{ Wh/km}$), and default connectors. |
| **#24 Bad numeric inputs & Battery Full** | - Non-positive battery or efficiency values rejected by Zod schema.<br>- Current charge $\%$ validated to $[0, 100]$.<br>- If charge is $100\%$, displays friendly notice: *"Battery already full · Charging top-up not required"*. |
