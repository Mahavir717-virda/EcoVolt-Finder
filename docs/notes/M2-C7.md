## 1. Booking Lifecycle State Machine

A booking progresses through strict state transitions:
```
[reserved] ──(scheduled window reached)──▶ [scheduled]
    │                                            │
    ├──(charging plugged in)────────────────────▶ [active] ──▶ [completed]
    │                                              │
    ├──(driver cancels within grace window)──────▶ [cancelled]
    │                                              │
    ├──(window passes without activation)────────▶ [expired]
    │                                              │
    └──(hardware / station malfunction)─────────▶ [failed]
```

## 2. Anti-Double-Booking & Concurrency Strategy (Edge Case #15)

To guarantee correctness under high concurrent booking requests without race conditions:
1. **Interactive Database Transaction (`prisma.$transaction`):**
2. **Row Lock & Availability Validation:**
   - Query total count of matching connectors for the station (`connector.totalCount`).
   - Count overlapping active bookings (`status IN ['reserved', 'scheduled', 'active']`) where:
     $$\text{existing.windowStart} < \text{requested.windowEnd} \quad \text{AND} \quad \text{existing.windowEnd} > \text{requested.windowStart}$$
   - If $\text{overlappingBookingsCount} \ge \text{connector.totalCount}$, the transaction immediately aborts and returns **HTTP 409 Conflict** (`CONNECTOR_UNAVAILABLE`).
3. **Atomic Reservation:**
   - Create booking record with status `reserved` and decrement connector `availableCount` if booking starts immediately.

## 3. Demand-Charge Peak Stacking Cap (Edge Case #16)

Charging stations face massive demand penalties when too many high-power chargers draw energy simultaneously during grid peak hours (e.g., 6:00 PM – 10:00 PM IST).
- The booking engine enforces a station-level concurrency cap:
  $$\text{concurrentActiveBookings} \le \text{station.maxConcurrentSessions} \quad (\text{default: } 80\% \text{ of total plugs during peak})$$
- If the peak concurrency cap is reached, the booking request returns HTTP 409 with a suggestion payload pointing the driver toward the nearest off-peak or high-renewable window.

---

## 4. Price Lock Persistence (Edge Case #17)

Every booking takes a `PriceQuote` snapshot computed by `PricingService.computeQuote`:
- The JSON object `{ baseTariff, providerMarkup, touAdjustment, finalPrice, isEstimate, validUntil }` is stored immutably in `Booking.lockedPrice`.
- Future updates to station tariffs or manager markups **never alter** this locked price.

---

## 5. Cancellation & Grace Rules (Edge Case #23)

- Drivers can cancel a booking via `PATCH /bookings/:id/cancel`.
- **Grace Window:** Allowed if $\text{currentTime} \le \text{booking.windowStart} - 15\text{ minutes}$.
- Once cancelled:
  - Status transitions to `cancelled`.
  - The reserved connector slot is immediately released for other drivers.
  - Returns HTTP 200 `{ status: "cancelled", refunded: true }`.
- If attempted outside the grace window, returns HTTP 400 `CANNOT_CANCEL_OUTSIDE_GRACE_WINDOW`.

## 6. Acceptance Criteria & Test Plan

1. **Concurrency Stress Test:** Two parallel simultaneous booking requests for the last remaining connector slot execute concurrently; exactly **one succeeds (201 Created)** and **one fails (409 Conflict)**.
2. `lockedPrice` is saved in the database matching the computed `PriceQuote`.
3. `PATCH /bookings/:id/cancel` within grace window marks booking `cancelled` and releases slot.
4. `GET /bookings` returns user-scoped bookings matching `/contracts/types.ts:Booking`.
5. TypeScript builds cleanly with 0 errors.
