**Why this layout?**
- Each sub-domain (`ingestion/`, `classify/`, ...) maps to one module that will grow into
  a real implementation in subsequent chunks (M3-C2 … M3-C10).
- Routers live separately from business logic so they can be thin (no logic, just delegation).
- `app/` is a proper Python package — importable as `from app.config import settings`.

## 2. Config / Env Approach

Using **`pydantic-settings`** (`BaseSettings`):

```python
class Settings(BaseSettings):
    grid_mode: Literal["live", "mock", "hybrid"] = "hybrid"
    electricity_maps_token: str = ""
    google_server_key: str = ""
    india_atlas_key: str = ""
    host: str = "0.0.0.0"
    port: int = 8000
    grid_cache_ttl_sec: int = 300
    mock_seed: int = 42
    version: str = "0.1.0"

    model_config = SettingsConfigDict(env_file=".env", extra="ignore")
```

- Single source of truth; injected via `Depends(get_settings)` or `settings` singleton.
- `.env` is loaded automatically; docker-compose passes env vars directly → no code change needed.
- `GRID_MODE` is a validated `Literal` — invalid values raise a startup error, not a silent mis-route.

## 4. How GRID_MODE Threads Through the Service

```
Request → Router → Domain module → Resolver (ingestion/)
                                       │
                           ┌───────────┼───────────┐
                         live        hybrid       mock
                           │            │            │
                    Electricity    try live →   MockGenerator
                    Maps API       cache →      (seeded random,
                    (raises on     mock         reproducible)
                    failure)
```

1. `settings.grid_mode` is the single switch.
2. **`live`**: calls external APIs; raises `HTTPException(503)` on failure.
3. **`mock`**: never calls external APIs; uses `MockGenerator(seed=settings.mock_seed)`.
4. **`hybrid`** *(default)*: tries live → on error falls back to in-memory cache → then mock.
   - Cache TTL: `settings.grid_cache_ttl_sec` (default 300 s).
   - The `GridSnapshot.quality` field tells the client which tier was hit: `live | cached | mock | stale`.

The resolver pattern means **no router-level `if GRID_MODE == ...`** — routers stay clean.
Domain modules call `await ingestion.resolve(zone_id)` and get back a tagged `GridSnapshot`.

In M3-C1 (stub phase), every endpoint ignores the resolver and returns the example JSON.
The resolver is wired in M3-C2.

## 5. Structured Logging

Using **`structlog`** with a JSON renderer in production and a coloured console renderer in dev:

```python
structlog.configure(
    processors=[
        structlog.contextvars.merge_contextvars_processor,
        structlog.processors.add_log_level,
        structlog.processors.TimeStamper(fmt="iso"),
        structlog.processors.JSONRenderer() if not DEV else structlog.dev.ConsoleRenderer(),
    ]
)
```

Every request logs `method`, `path`, `status_code`, `duration_ms`, `grid_mode`.
Errors log the full traceback in the `exc_info` field.
